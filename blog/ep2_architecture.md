## 1인 개발의 한계와 AI라는 동료

teding은 기획, 디자인, 백엔드, 프론트엔드까지 모두 혼자서 진행해야 하는 1인 프로젝트였습니다. 보통 이 정도 규모(인증, 대시보드, 4단계 학습 플로우, AI 파이프라인, Admin 페이지)의 앱을 혼자 만들려면 최소 2~3주가 걸립니다.

하지만 저는 정확히 **4일** 만에 MVP를 오픈했습니다. (04/05 시작, 04/09 1차 배포)

이 속도의 비결은 단순히 "AI 코딩 도구를 썼기 때문"이 아닙니다. **"두 개의 AI 모델이 서로의 강점을 발휘하도록 시스템을 설계했기 때문"**입니다.

## Claude Code와 Gemini CLI: 듀얼 페어 프로그래밍

저는 두 가지 CLI 기반 AI 에이전트를 동시에 운용했습니다. 일종의 'AI 듀얼 페어 프로그래밍'입니다.

| 역할          | AI 도구     | 강점                              | teding에서의 담당 업무                                         |
| ------------- | ----------- | --------------------------------- | -------------------------------------------------------------- |
| **Architect** | Claude Code | 추론 능력, 대규모 리팩토링 안정성 | DB 스키마 설계, Auth 아키텍처, API 라우트 로직, 앱 패키징 전략 |
| **Builder**   | Gemini CLI  | 빠른 반응성, 컴포넌트 구조화 능력 | UI 컴포넌트 양산, TailwindCSS 스타일링, 버그 수정, SEO 세팅    |

이 두 명의(?) AI 개발자가 하나의 코드베이스에서 엉키지 않고 일하게 하려면 **완벽한 소통의 기준점(SSoT, Single Source of Truth)**이 필요했습니다.

그 역할을 한 것이 바로 `docs/` 폴더입니다.

## 아키텍처 문서가 곧 프롬프트다: `docs/` 오케스트레이션

AI 기반 개발에서 가장 흔히 겪는 문제가 있습니다.
_"어제까지 잘 되던 스키마를 오늘 새 세션에서 옛날 버전으로 짜버렸다."_
이른바 컨텍스트 유실로 인한 타임슬립 현상이죠.

이를 막기 위해 저는 **모든 컨텍스트를 코드가 아닌 마크다운 문서에 영속화**시켰습니다.

### 1. `WORKFLOW.md`: AI를 통제하는 헌법

세션을 켤 때마다 AI에게 "WORKFLOW.md를 읽고 시작해"라고 명령합니다. 이 파일 안에는 다음과 같은 제약이 적혀 있습니다.

- "Supabase 클라이언트는 반드시 싱글턴 사용"
- "DB 접근은 서버 API Route에서만 할 것"
- "상태 관리는 useState 대신 URL SearchParams 지향"

### 2. `ARCHITECTURE.md`: 환각 방지 백신

스키마나 규칙이 바뀌면 코드를 수정하기 **전에** 무조건 이 파일부터 수정합니다.
예를 들어 `learning_materials` 테이블을 만들 때 컬럼 스펙과 이유를 적어둡니다. 그러면 Claude가 짠 백엔드를 다음 날 Gemini가 읽고 정확한 타입으로 UI를 만들어냅니다.

### 3. `tasks/TASK_XXX.md`: 작업 지시서

작업을 더 작은 단위로 쪼개어 "이 태스크의 목표, 현재 상황, 완료 기준"을 명확히 적습니다. AI는 이 기준을 통과할 때까지 코드를 작성하고 검증합니다.

```
[사용자] → (태스크 지시) → [Claude / Gemini]
                               │
                               ▼
                        [docs/ 폴더 열람]
       (WORKFLOW.md, ARCHITECTURE.md, TASK_XXX.md)
                               │
                               ▼
                       [코드 생성 및 검증]
```

이 체계 덕분에 회귀 버그(Regression Bug) 0건이라는 놀라운 성과를 거둘 수 있었습니다.

## 전역 캐싱과 원자적 저장: `learning_materials`

이제 본격적인 아키텍처 이야기를 해보겠습니다.

teding의 비용을 아껴주는 핵심 구조는 **전역 캐싱**입니다.
관리자가 매일 영상을 등록하면, 첫 사용자가 접근할 때 AI가 학습지를 생성합니다. 이후의 모든 사용자는 이미 만들어진 데이터를 빠르게 받아보기만 합니다.

초기에는 지문(Worksheets), 핵심표현(Phrases), 구문분석(Sentences)을 각기 다른 테이블에 저장하려고 했습니다. 그런데 문제가 생겼습니다.
_만약 지문은 저장됐는데 핵심표현 저장 단계에서 에러가 난다면?_
일명 부분 실패(Partial Failure)입니다. 사용자는 반쪽짜리 학습 자료를 보게 되겠죠.

이를 막기 위해 과감히 3가지 데이터를 **`learning_materials`라는 단일 테이블의 `jsonb` 컬럼**들로 합쳤습니다. API 한 번 호출(`GET /api/generate`)로 모든 과정을 마친 뒤 딱 한 번의 `upsert`만 실행합니다.
이로써 **100% 원자성(Atomicity)**을 확보하고 부분 실패의 위험을 설계 단계에서 차단했습니다.

## PLG(Product-Led Growth) 전환기: 로그인 장벽 무너뜨리기

MVP 오픈 후 가장 큰 고민은 **"접속하자마자 뜨는 로그인 창"** 이었습니다.

앱을 만들 때는 당연히 모든 데이터를 사용자 단위로 추적해야 하니 `AuthGuard`로 페이지를 감쌌죠. 하지만 입장을 바꿔 생각해보니, 어떤 앱인지 보지도 못했는데 구글 로그인을 하라는 건 폭력적이기까지 했습니다.

**전환율을 높이려면 가치(Value)를 먼저 경험하게 해야 한다.**

저는 즉시 설계를 바꿨습니다.

1. `/admin` 경로만 미들웨어(`proxy.ts`)에서 강력 차단
2. 학습 1~4단계와 대시보드 콘텐츠 **전면 개방** (로그인 없이도 학습 가능)
3. Step 4 **완료 버튼**을 누를 때, 혹은 대시보드에서 **내 기록을 자세히 보려 할 때** 전역 AuthModal을 팝업

사용자가 "와 이 앱 진짜 좋다. 내일도 해야지, 이 기록 저장해 둬야지"라고 느끼는 **가장 전환 의지가 높은 순간**에 자연스럽게 로그인을 묻는 구조입니다. 카카오톡으로 공유된 링크를 타고 들어온 사람도 곧바로 영어 학습을 경험할 수 있게 되었습니다.

4일 만에 MVP를 올릴 수 있었던 것은 단순히 코딩 속도가 빨라서가 아닙니다.
**AI가 잘 짜는 구조와 인간이 잘 기획하는 맥락을 `docs`라는 다운으로 연결한 것, 그리고 데이터와 사용자 플로우를 가장 단순하고 확실한 방향으로 재설계한 것.**
