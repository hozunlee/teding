## 아내가 결제 버튼을 누르려 했다

해외여행을 다녀오는 비행기 안, 우리는 늘 굳게 다짐합니다.

_"올해는 진짜 영어 공부한다. 영어 너 죽었다."_

하지만 12월이 되면 결국 죽어 있는 건 나의 결심뿐입니다.

한국이라는 환경에서 자연스럽게 영어를 사용하기란 불가능에 가깝습니다. 집에서 "우리 오늘부터 영어로만 말해보자!"라고 선언해 봐도, *"Hi, nice to meet you, How are you, Thank you, Bye"*로 끝나는 허무한 대화가 전부죠. 결국 우리는 다시 유튜브를 켜고 '2026 영어 공부법'을 검색합니다. 그러다 휘황찬란한 마케팅 문구에 홀려 어느새 영어 학습 앱 결제창에 지문을 찍고 있는 나를 발견합니다.

**'하루 10분이면 원어민이 된다고?'**

여유롭고 유창하게 영어를 구사하는 내 모습을 상상하며 기꺼이 카드를 긁습니다. 시간과 노력을 들이는 대신, **'돈'**이 내 영어 실력을 해결해 주리라 믿으면서요.

그런데 어느 날, 아내가 또 다른 영어 앱의 연간 구독 결제 버튼에 손을 올리고 있었습니다.

_잠깐만. 이거 내가 만들 수 있잖아._

## 왜 TED-Ed인가

수영을 배울 때 가장 먼저 하는 일은 숨을 참고 물과 친해지는 것입니다. 영어도 마찬가지여야 합니다. '공부'라는 압박을 버리고, 일단 재미있고 자연스럽게 스며들어야 합니다.

방법을 찾던 중, "이 방법으로 영어가 늘지 않으면 삭발하겠다"는 한 유튜버의 영상을 보았습니다. 그가 제시한 해답은 바로 **TED-Ed**였습니다.

TED-Ed는 기존의 영어 학습 콘텐츠와 근본적으로 다른 세 가지를 가지고 있었습니다:

| 특징          | 기존 학습 앱             | TED-Ed                                      |
| ------------- | ------------------------ | ------------------------------------------- |
| **길이**      | 30분+ 강의 → 집중력 한계 | **5분 내외** → 출퇴근길에 가볍게            |
| **영상 품질** | 슬라이드 + 말하는 머리   | **아카데미급 애니메이션** → 눈을 뗄 수 없음 |
| **스크립트**  | 별도 구매 or 없음        | **완벽한 자막 + 스크립트** 무료 제공        |

이거라면 지루한 '공부'가 아니라 매일 즐기는 '콘텐츠'가 될 수 있겠다고 확신했습니다.

머릿속에 학습 사이클이 그려졌습니다:

```
시청 → 스크립트 확인 → 학습지(핵심 단어·문법·문제) → 핵심 구문 분석 → 완료
```

**총 15분.** 커피 한 잔 마시는 시간이면 됩니다.

---

## 문제는 '지속성'이었다

완벽한 학습 사이클이 그려졌지만, 현실적으로 이 과정을 **매일** 직접 하기란 불가능에 가까웠습니다.

매일 아침:

1. TED-Ed에서 적당한 영상을 고르고
2. 스크립트를 복사하고
3. 모르는 단어를 사전에서 찾고
4. 핵심 문법을 정리하고
5. 퀴즈를 직접 만들어야 합니다

이 수동 작업을 3일도 못 버틸 게 뻔했습니다. 결국 우리가 영어를 포기하는 이유는 **의지의 문제가 아니라 과정의 마찰 비용**이 너무 크기 때문입니다.

그래서 결심했습니다. **이 마찰 비용을 0으로 만들자.**

## AI가 해결할 수 있었다

2026년의 개발자에게는 강력한 도구가 있었습니다. **Gemini 2.5 Flash.**

스크립트를 넣으면 AI가 자동으로:

- **A2 수준의 쉬운 영어 지문**을 작성하고
- **핵심 단어장**을 정리하고
- **MCQ/단답형 퀴즈**를 만들어주고
- **핵심표현 5개**를 뽑아 예문과 함께 설명하고
- **구문분석**으로 왜 이 문장이 이렇게 쓰였는지 풀어줍니다

관리자(저)가 매일 아침 TED-Ed 영상 하나만 선택하면, **나머지는 전부 AI가 처리합니다.**

그리고 가장 중요한 것: 이 학습 자료는 **첫 번째 사용자가 접근한 순간 1회만 생성**됩니다. 두 번째 사용자부터는 DB에 캐싱된 자료가 즉시 로드됩니다. API 비용? **영상 1편당 Gemini API 호출 1회.** 월 30회면 충분합니다.

## 기술 스택, "왜 이것이어야 했는가"

무작정 코드를 쓰기 전에, 세 가지 제약 조건을 먼저 정했습니다:

1. **1인 개발** → 풀스택을 단일 코드베이스로
2. **빠른 MVP** → 4일 안에 동작하는 프로토타입
3. **앱 출시 가능성** → 웹 코드를 네이티브로 재사용

이 제약에서 기술 스택이 자연스럽게 결정되었습니다:

### Next.js 16 (App Router)

SSR로 SEO를 확보하면서 API Routes로 별도 백엔드 서버 없이 풀스택 구현. `output: 'export'`로 Capacitor 앱 빌드도 가능. **프론트엔드와 백엔드가 같은 리포에 있다는 것**이 1인 개발에서 가장 큰 무기.

### Supabase

Auth(Google OAuth + Email) · PostgreSQL(RLS) · Storage(이미지 업로드)를 단일 서비스로 해결. Firebase 대비 **SQL 기반이라 복잡한 쿼리가 자유롭고**, RLS로 보안 정책을 코드가 아닌 DB 레벨에서 선언적으로 관리할 수 있었음.

### Gemini 2.5 Flash-Lite (+ Claude 폴백)

`responseMimeType: 'application/json'` 옵션이 결정적. API가 JSON을 직접 반환하므로 마크다운 펜스 파싱 코드가 필요 없음. 장애 시 Claude로 자동 전환하는 폴백 구조도 구축.

## 그리고 가장 중요한 결정: AI와 함께 개발하기

여기서 "AI를 활용해서 학습 자료를 만든다"는 것 외에, 또 하나의 AI 활용이 있었습니다.

**개발 자체를 AI와 함께 하는 것.**

저는 **Claude Code**와 **Gemini CLI**를 동시에 사용하는 듀얼 AI 페어 프로그래밍 체계를 구축했습니다.

- **Claude Code**: DB 설계, 인증 아키텍처, API 라우트 초안 생성, 대규모 리팩토링
- **Gemini CLI**: UI 컴포넌트 양산, 디자인 시스템 적용, 빠른 버그 수정, CSS/Tailwind 작업

둘 다 같은 `docs/` 폴더의 문서를 읽습니다. `WORKFLOW.md`는 협업 규칙을, `ARCHITECTURE.md`는 현재 DB 스키마를, `tasks/TASK_XXX.md`는 각 태스크의 목표와 완료 기준을 담고 있습니다.

이 체계 덕분에:

- **세션이 끊겨도** 문서에 모든 컨텍스트가 영속화되어 즉시 복구
- **AI 환각으로 인한 회귀 버그 0건** — `ARCHITECTURE.md`가 스키마의 SSoT(Single Source of Truth)
- **MVP 4일 완성** — 단순히 "AI가 코드를 써줬다"가 아니라, **AI의 출력이 일관되도록 시스템을 설계한 것**이 핵심

이 개발 방법론에 대해서는 EP.2에서 더 자세히 다루겠습니다.

```
                      ▼

    ┌────────────────────────────────────┐
    │      학습지 · 핵심표현 · 구문분석     │
    │      (learning_materials 테이블)    │
    └────────────────┬───────────────────┘
                     ▼
    ┌────────────────────────────────────┐
    │         사용자 학습 4단계             │
    │  Step 1: 무자막 시청                 │
    │  Step 2: 스크립트 확인               │
    │  Step 3: 학습지 (퀴즈 + 인쇄)        │
    │  Step 4: 핵심표현 + 구문분석          │
    │  → 완료: 난이도 평가 + 공유           │
    └────────────────────────────────────┘
```
